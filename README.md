# 考研择校 RAG 系统

带溯源机制 + 结构化数据校验的 RAG 系统，核心目标：降低大模型幻觉，体现工程化思维

## 核心亮点

- **四层防线降低幻觉**：检索质量 → 生成约束 → 数据校验 → 置信度拒答
- **混合检索 + Reranker**：BM25 + 向量检索 + RRF 融合 + 精排，工业级检索方案
- **答案溯源机制**：每句话标注来源，用户可点击查看原始文档
- **结构化数据校验**：自动比对回答中的数字与真实数据，防止关键信息出错
- **量化抗幻觉**：实测幻觉拦截率从标准 RAG 的 0% 提升到 100%（校验标记 + 拒答）
- **工程化设计**：前后端分离、依赖注入、配置管理、量化评估体系

## 技术栈

| 组件 | 选择 | 理由 |
|------|------|------|
| LLM | DeepSeek API | 性价比高，中文效果好，兼容 OpenAI 格式 |
| Embedding | BAAI/bge-small-zh-v1.5 | 中文专用，本地运行免费，效果好 |
| Reranker | BAAI/bge-reranker-base | 中文精排模型，本地运行 |
| 向量数据库 | ChromaDB | 轻量级，Python 原生，上手快 |
| BM25 | rank_bm25 | 纯 Python，无需外部服务 |
| 后端 | FastAPI | 现代、高性能、自动文档 |
| 前端 | Streamlit | 快速构建数据应用界面 |

## 快速开始

```bash
# 安装依赖
pip install -r requirements.txt

# 配置 API Key
# 编辑 .env 文件，填入你的 DeepSeek API Key

# 数据入库
python -m backend.services.ingestion

# 启动后端（端口 8000）
uvicorn backend.main:app --reload

# 启动前端（新开终端）
streamlit run frontend/app.py
```

### 运行测试与评估

```bash
# 单元/集成测试（在 backend/tests/ 下）
python -m backend.tests.test_validation   # 结构化数据校验
python -m backend.tests.test_confidence   # 置信度升级（召回覆盖率）
python -m backend.tests.test_retrieval    # 混合检索
python -m backend.tests.test_integration  # 端到端集成测试

# 幻觉率评估（需要真实 DeepSeek Key）
python -m backend.evaluation.evaluate         # 纯LLM vs 标准RAG vs 本系统
python -m backend.evaluation.evaluate_compare # 对比/开放题幻觉拦截

## 四层防线架构

```
用户提问
    │
    ▼
┌─────────────────────────────────────┐
│  第1层：检索质量保障                 │
│  BM25 + 向量混合检索 → RRF融合      │
│  → Reranker精排 → 过滤低相似度结果   │
├─────────────────────────────────────┤
│  第2层：生成约束                     │
│  System Prompt 强制引用标注          │
│  每句话标注来自哪个文档               │
├─────────────────────────────────────┤
│  第3层：结构化数据校验                │
│  正则提取数字 → 与JSON标准答案比对    │
│  不一致的数字标红警告                 │
├─────────────────────────────────────┤
│  第4层：置信度评估 + 拒答             │
│  单文档相关性 + 召回覆盖率 双维度     │
│  低置信度直接回复"暂无相关信息"       │
└─────────────────────────────────────┘
    │
    ▼
带溯源标注 + 校验标记的回答
```

## 已知优化方向

### 1. 置信度指标（已升级：召回覆盖率）

**现状**：置信度已从"单文档相关性"升级为「**相关性 + 召回覆盖率**」双维度。`retrieval.py` 的 `assess_coverage()` 判断问题提到的学校是否都被召回，覆盖率满分且单文档分数高于下限（`RECALL_FLOOR=0.15`）时放行，解决对比/开放题的误拒答；分数极低（如"医学部"）仍拒答。

**剩余改进方向**：

| 方案 | 做法 |
|------|------|
| 问题意图分类 | 识别事实查询 vs 对比/推荐，分场景设更精细的阈值 |
| 聚合 Top-K | 用 Top-3 加权融合进一步替代 Top-1 单点分数 |

### 2. 结构化校验的正则健壮性

`validation.py` 用正则提取数字，已支持跨行（`(?s)`）和"录取人数为 X 人"等表述。但正则校验本质是脆弱的，后续可替换为 NER 或小模型抽取数字，再与标准答案比对。

### 3. 后续功能扩展

- **真实数据采集与结构化**（当前最大难点）：现有 `data/raw` 是开发用模拟数据，真实数据需从研招网、各高校研究生院官网、历年拟录取名单公示等分散来源采集。难点在于：
  - 数据分散在几十个网站、格式五花八门，且**每年更新**；
  - 招生简章多为 PDF/网页，需爬虫采集 + PDF 解析 + 数据清洗；
  - 从非结构化文本里抽取分数线/报录比/录取人数等字段，抽取易错，需人工或规则校验。
- 多轮对话（短期记忆：对话历史管理）
- 长期记忆（用户偏好/历史问答，个性化推荐）
- 知识图谱（院校-专业-导师实体关系，Graph + Vector 双路检索）
- Docker 容器化部署
